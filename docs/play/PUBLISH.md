# From this build to a Play test

This is a test candidate, not a declaration that the complete product roadmap or Play review has passed. No Play Console write or public deployment is performed by the build.

1. Test the preview on a physical phone with synthetic entries: launch, rotate, enable lock, deny and grant notifications, share a photo, log a cycle temperature, back up, restore into a separate install and confirm the results. Try large text and TalkBack. Check reminder delivery after a reboot. Keep existing private data in the original installation.
2. Review the store description, screenshots, feature graphic and icon. Use synthetic screenshots only. Confirm ownership or distribution rights for **every** bundled illustration, deck description, font and dependency. Confirm your publisher name and public support contact. Finalize and host a public read-only privacy page; the supplied HTML is a draft until its publisher/contact fields are completed. Enter the policy URL in Play Console and review the matching in-app notice.
3. The production artifact is **app-release.aab**, application ID **com.lilyly.app**, code 32. It is deliberately unsigned. Sign a copy with the publisher-controlled upload key for that Play package; never upload a preview, a debug-signed artifact or an unsigned bundle. For an existing Play listing use its registered upload key and a version code higher than every previously uploaded code. Keep the key and password out of GitHub and chat. Android Studio: Build → Generate Signed Bundle / APK → Android App Bundle → choose the app and your upload keystore → release. Alternatively use the included signing script with JDK 17. Compare the signer’s SHA-256 fingerprint with your registered upload certificate before submission.
4. In Play Console select the testing track, enable Play App Signing and upload the signed production AAB. Complete app access, content rating, ads, target audience, Health apps, Data safety and privacy declarations for the build you upload. Check the pre-launch report, device compatibility and any target SDK / native-library warnings. Run Play-delivered install and upgrade tests. An emulator preview launch is not a substitute.
5. If your personal developer account was created after 13 November 2023, verify whether the closed-test requirement applies: at least 12 testers continuously opted in for 14 days before applying for production access. Production submission and pricing are owner decisions.

## Declaration worksheet (review before submitting)

- Health features to review: period and fertility tracking, mental health, sleep management and medication management. Review any other applicable categories against the final listing. Health records are manually entered; no Health Connect integration.
- No Lilyly account, ads, analytics or backend in this build. The production package check rejects Internet permission. Review any future dependency before changing the disclosures. Device-local processing alone is distinct from transmission off-device. Explicit document-provider exports, backups, PDF sharing and delegated links must be evaluated under the current form definitions.
- Device authentication is handled by Android. No raw biometrics are stored by Lilyly. Medication alerts are optional. Photos/books are chosen through Android document pickers or share intents. Private file storage is not the same as encrypting each individual media asset.
- Records are retained on device until removed. Clearing app data removes the local installation’s content. Other installs, external originals, user-created backups and PDFs are managed separately. Use only a public support address the publisher can monitor.
